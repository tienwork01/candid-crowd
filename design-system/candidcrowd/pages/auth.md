# Authentication UI

- Routes: `/login` and `/register`. UI only; no Better Auth dependency, API calls, OAuth redirects, sessions, credential logging or persistence. Submit/provider actions display an unavailable status rather than simulated success. Integrate Better Auth later at the form handlers.
- UI UX Pro Max queries: `consumer photography authentication`, retry `minimal authentication form`; neither supplies a complete product match. Retain MASTER tokens, Cormorant Garamond and DM Sans. Adopt restrained form hierarchy and clear labels; reject generated motion-heavy page patterns.
- Focused searches: `accessible authentication`, `form labels password visibility`. Allow paste and password managers, use autocomplete, show/hide password controls, native required/email validation and an unchecked required terms checkbox. Signup minimum length of eight is provisional until auth policy is implemented.
- One unframed form column, a full-height photographic band on desktop, photo after the form on mobile. No 3D on authentication routes. BEM classes in `auth.css`, fixed 16px input text, semantic palette, 48px primary controls and reduced-motion support.
- Login: email/password; registration: full name/email/password/terms. Google and Apple buttons on both. Reset, terms and privacy open accessible availability notices. No published legal terms are implied.
- Provider glyphs: Simple Icons Google and Apple SVGs from `https://github.com/simple-icons/simple-icons/tree/develop/icons`, stored locally under `public/icons/`. Existing project photography is reused.
- Validation: production build and lint pass. Four auth tests and two affected homepage navigation tests pass on desktop/mobile, including axe, consent, visibility, provider notices and no credential persistence. `node scripts/auth-visual-audit.mjs` captures both routes at 375, 390, 430, 768, 1024, 1440 and 1920px with decoded images and no horizontal overflow. Physical devices and real authentication are outside this UI milestone.
